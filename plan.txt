P0 — Correctness Bugs (Fix First)
P0-1: Coordinate-System Mismatch Between trimesh and Open3D
File: voidx_pipeline.py, method VoidXPipeline.load_mesh

Problem: You load the mesh twice — once with trimesh (for raycasting in Phase 2) and once with Open3D (for rendering in Phase 1). They may apply different default transforms to GLB files, causing the skeleton (computed in Open3D space) to be misaligned with the raycast target (in trimesh space). This is a silent bug.

Current code:

def load_mesh(self, mesh_path: str):
    import trimesh
    import open3d as o3d
    scene = trimesh.load(mesh_path)
    if isinstance(scene, trimesh.Scene):
        geoms = []
        for node in scene.graph.nodes_geometry:
            transform, geometry_name = scene.graph.get(node)
            geom = scene.geometry[geometry_name]
            geom.apply_transform(transform)
            geoms.append(geom)
        self._trimesh_mesh = trimesh.util.concatenate(geoms)
    else:
        self._trimesh_mesh = scene
    self._mesh = o3d.io.read_triangle_mesh(mesh_path)
    self._mesh.compute_vertex_normals()
    self.cortex.init_visualizer(self._mesh)
    return self._trimesh_mesh
Fixed code — derive trimesh FROM Open3D so both share identical coordinates:

def load_mesh(self, mesh_path: str):
    import trimesh
    import open3d as o3d

    # Load with Open3D first (authoritative for rendering coordinate system)
    self._mesh = o3d.io.read_triangle_mesh(mesh_path)
    self._mesh.compute_vertex_normals()

    # Derive trimesh FROM the Open3D mesh — guarantees identical coordinates
    vertices = np.asarray(self._mesh.vertices).copy()
    faces = np.asarray(self._mesh.triangles).copy()
    self._trimesh_mesh = trimesh.Trimesh(
        vertices=vertices, faces=faces, process=False
    )
    # Fix for non-watertight meshes: don't merge vertices
    self._trimesh_mesh.metadata["source"] = "open3d_derived"

    self.cortex.init_visualizer(self._mesh)
    return self._trimesh_mesh

if lengths:

return diag * 0.1

P0-3: VCE Centroid Bias (Underestimates True Centering Error by ~2×)
File: voidx_metrics.py, function volumetric_centering_error

Problem: The cross-section center c is computed as np.mean(hit_points, axis=0) where hit_points are first-exit points of rays fired from the joint. For a symmetric cross-section, this centroid equals (proj + c_true) / 2 — biased toward the joint by half the offset. The measured VCE is therefore approximately half the true centering error.

Mathematical proof of the fix: For 8 uniform rays in 2D, the centroid of exit points = (p + c_true) / 2. Therefore the unbiased estimate is c_true = 2 * centroid - p. (I verified this: for p = c_true, both sides give c_true; for p on the surface, both sides give c_true.)

Current code:

mesh_cross_section_center = np.mean(hit_points, axis=0)
radial_err = float(np.linalg.norm(p - mesh_cross_section_center))
errors.append(radial_err / local_diameter)

Fixed code:

# Unbiased center estimate: for uniform rays on a symmetric cross-section,
# centroid of exit points = (proj + c_true)/2, so c_true = 2*centroid - proj
mesh_cross_section_center = 2.0 * np.mean(hit_points, axis=0) - proj
radial_err = float(np.linalg.norm(p - mesh_cross_section_center))
errors.append(radial_err / local_diameter)

Verification with a synthetic cylinder:

import trimesh, numpy as np
cyl = trimesh.creation.cylinder(radius=1.0, height=10.0)
cyl.apply_translation([0, 0, 0])  # center at origin

# Joint at exact center → VCE should be 0.0

# Joint offset by 0.5 (half-radius) → VCE should be 0.25
fake_pred_offset = {"pelvis": {"x": 0.5, "y": 0, "z": 0}}
vce = volumetric_centering_error(fake_pred_offset, cyl)
assert abs(vce - 0.25) < 0.05, f"Expected ~0.25, got {vce}"

# Joint on surface → VCE should be ~0.5
fake_pred_surface = {"pelvis": {"x": 1.0, "y": 0, "z": 0}}
vce = volumetric_centering_error(fake_pred_surface, cyl)
assert abs(vce - 0.5) < 0.05, f"Expected ~0.5, got {vce}"

Expected impact: VCE will approximately double (e.g., 0.266 → ~0.53). This is more honest. Update Table IV and the discussion in Section VI-C. The large std (0.505) will likely also scale up.

P1-2: Use a True Orthographic Renderer (or Document the Approximation)
File: voidx_pipeline.py (CortexVision.init_visualizer) — and the paper text.

Problem: Open3D's Visualizer uses a pinhole camera. Scaling focal length by 20 reduces but doesn't eliminate perspective distortion. The residual perspective term scales as Z/d × (1/20), which for a character filling the frame (Z varying by ~20% of d) gives ~1% residual distortion — small but not zero.

Option A (preferred): Switch to pyrender which has a true OrthographicCamera:

# In CortexVision.__init__, replace Open3D visualizer with:
import pyrender
class CortexVision:
    def __init__(self, config):
        self.config = config
        self._mesh = None
        self._scene = None
        self._camera = None
        self._renderer = pyrender.OffscreenRenderer(
            viewport_width=config.render_resolution,
            viewport_height=config.render_resolution,
        )

    def init_visualizer(self, mesh):
        # Convert Open3D mesh to pyrender mesh (share vertices)
        vertices = np.asarray(mesh.vertices)
        faces = np.asarray(mesh.triangles)
        pr_mesh = pyrender.Mesh.from_trimesh(
            trimesh.Trimesh(vertices=vertices, faces=faces),
            material=pyrender.MetallicRoughnessMaterial(
                baseColorFactor=list(self.config.mesh_skin_tone) + [1.0],
                metallic=0.0, roughness=1.0
            )
        )
        self._scene = pyrender.Scene(
            bg_color=list(self.config.background_color) + [1.0]
        )
        self._scene.add(pr_mesh)

        # TRUE orthographic camera
        cam = pyrender.OrthographicCamera(
            xmag=1.0, ymag=1.0, znear=0.05, zfar=100.0
        )
        cam_pose = np.eye(4)
        cam_pose[:3, 3] = [0, 0, 5]  # 5 units in front
        self._cam_node = self._scene.add(cam, pose=cam_pose)

import numpy as np
import trimesh
import open3d as o3d
from voidx_pipeline import VoidXPipeline

def test_coordinate_alignment():
    """Verify Open3D and trimesh meshes have identical bounds."""
    pipe = VoidXPipeline()
    # Use a known test mesh
    trimesh_mesh = pipe.load_mesh("tests/data/sample_character.glb")

    o3d_bbox = pipe._mesh.get_axis_aligned_bounding_box()
    o3d_min = np.asarray(o3d_bbox.get_min_bound())
    o3d_max = np.asarray(o3d_bbox.get_max_bound())
    tri_min = trimesh_mesh.bounds[0]
    tri_max = trimesh_mesh.bounds[1]

    assert np.allclose(o3d_min, tri_min, atol=1e-4), \
        f"Min bounds disagree: Open3D={o3d_min}, trimesh={tri_min}"
    assert np.allclose(o3d_max, tri_max, atol=1e-4), \
        f"Max bounds disagree: Open3D={o3d_max}, trimesh={tri_max}"

P2-3: Add a VCE Metric Test
File: new file tests/test_vce_metric.py

import numpy as np
import trimesh
from voidx_metrics import volumetric_centering_error

def test_vce_centered_joint():
    """A perfectly centered joint should have VCE ≈ 0."""
    cyl = trimesh.creation.cylinder(radius=1.0, height=10.0, section=32)
    pred = {"pelvis": {"x": 0, "y": 0, "z": 0}}
    vce = volumetric_centering_error(pred, cyl)
    assert vce < 0.05, f"Centered joint VCE should be ~0, got {vce}"

def test_vce_surface_joint():
    """A joint on the surface should have VCE ≈ 0.5."""
    cyl = trimesh.creation.cylinder(radius=1.0, height=10.0, section=32)
    pred = {"pelvis": {"x": 1.0, "y": 0, "z": 0}}
    vce = volumetric_centering_error(pred, cyl)
    assert abs(vce - 0.5) < 0.1, f"Surface joint VCE should be ~0.5, got {vce}"

def test_vce_half_radius():
    """A joint at half-radius should have VCE ≈ 0.25."""
    cyl = trimesh.creation.cylinder(radius=1.0, height=10.0, section=32)
    pred = {"pelvis": {"x": 0.5, "y": 0, "z": 0}}
    vce = volumetric_centering_error(pred, cyl)
    assert abs(vce - 0.25) < 0.1, f"Half-radius VCE should be ~0.25, got {vce}"
